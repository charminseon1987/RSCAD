## `load_calc.py` — 부하 집계·피상전력·용량여유

겨누는 것은 대장 §3 의 **V-02** 다.

> TR4 부하계산에서 PV 119.6 kW 를 피상전력 kVA 에서 차감한 산식의
> 기술적 타당성 (역률·접속위치·시간별 출력)

**kVA 에서 kW 를 뺀다.** 여기에 둘이 숨는다.

### ① 무효전력을 빼먹는다

```
설계서:  S' = S − P_pv                 (kVA − kW)
올바름:  S' = |(P − P_pv) + jQ|
```

어느 쪽이 큰지는 정해져 있다 — **설계서 쪽이 항상 작거나 같다.** Q 가 0 이
아니면 반드시 작다. 즉 변압기가 받는 부하를 **작게 본다** → 여유율이 실제보다
크게 나온다. **틀리는 방향이 안전한 쪽이 아니다.**

`--demo` 가 보이는 거동 (예시값, 설계도서 값 아님):

| | 값 |
|---|---|
| 부하 P=800 kW, 역률 0.80 → S | 1,000.0 kVA |
| 설계서 방식 `S − P_pv` | 800.0 kVA |
| 복소전력 방식 `|(P−P_pv)+jQ|` | 848.5 kVA |
| **차이** | **48.5 kVA (벡터값의 5.7%)** |
| 1,000 kVA 변압기 여유율 | 설계서 20.00% vs 벡터 15.15% → **4.85 %p 과대** |

### ② 동시발생을 가정한다

최대부하 시각과 PV 최대출력 시각이 같다고 보고 전량을 뺀다. `coincidence()`
가 **그 시각의** PV 출력을 뽑아 과다차감분을 낸다. 예시에서는 최대부하 시각의
PV 가 최대출력의 5% 뿐이어서 190 kW 가 과다차감이었다.

→ 이 둘을 분리해 정량화하는 것이 3.4 의 산출물이다. **두 방식을 나란히
계산한다** — 한쪽을 지우고 "올바른 값" 만 내면 비교가 사라진다.

## 값을 지어내지 않는다

- **기본값이 없다.** 역률·수용률·변압기 정격 전부 호출자가 준다. 인자를
  안 주면 도는 게 아니라 **터진다.** 설계도서를 못 열었으므로 여기에 기본값을
  박으면 그 값이 논문까지 흘러간다.
- `LoadItem` 은 `source`(문서·쪽)와 `verification` 을 함께 받는다.
  검증상태는 대장·일지와 **같은 다섯 개**만 — `원문 확인` · `교차검증 완료` ·
  `불일치` · `연구 가정` · `미확인`. 다른 문자열을 주면 터진다.
- `--demo` 수치는 **형식 확인용**이다. 전사본의 TR1~TR4 값은 전부 `미확인`
  이고 (대장 §2) 여기에 옮기지 않았다.

## 같이 들어 있는 함정 탐지

`naive_kVA_sum()` — 각 부하의 kVA 를 그냥 더한 값. **틀린 방법**이고 대조용
으로만 둔다. 역률이 다른 부하들의 kVA 합은 실제 합성 피상전력보다 **크다**.
집계표가 이 방식이면 변압기를 과대 선정하게 되고, 그건 V-02 와 **반대 방향**의
오차다. `aggregate()` 결과와 비교해 차이를 보고한다.
