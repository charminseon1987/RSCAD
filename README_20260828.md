# GFM 22-state 소신호 모델

2단 PV+ESS Grid-Forming 인버터의 소신호 상태공간 모델과 SCR–X/R 강건성 경계 분석.

- **모델 버전:** `v3-22state` (22 = DC 8 + AC 14)
- **ζ 기준:** 0.64 (UNIFI Category 3)
- 조연호 · 연세대 스마트그리드 연구실

> [!] `J`는 **가상 관성**(PSO 대상 파라미터)입니다.
> 야코비안은 코드 전체에서 `A`로 표기합니다. 혼동 주의.

## Simulation 파일

| 파일 | 역할 | 실행 |
|---|---|---|
| `model.py` | 22-state 심볼릭 정의. 상태벡터·상태방정식 `f(x,u)` 구성 → SymPy `jacobian()`으로 `A_sym`·`B_sym` 유도 → `lambdify`로 수치 함수화 | 라이브러리 (단독 실행 시 커플링 자가검사) |
| `op.py` | 동작점 계산. SCR·X/R 입력 → `scipy.fsolve`로 `f(x,u)=0` 풀어 `x₀` 반환. δ가 SCR 따라 22°→62° 움직이는 걸 뽑는 부분. `jacobian()`·`fd_jacobian()` 제공 | 라이브러리 |
| `runner.py` | **메인 진입점.** 스윕 실행 → 유한차분 검산 → 대역별 ζ → 커플링 효과 → `results/{run}/` 저장 + `LATEST.json` 갱신 | ✅ |
| `pf.py` | 참여계수(Participation Factor)로 모드 귀속 확정. 주파수 대역 분류의 검증 수단 | ✅ |
| `xval.py` | 선형화 유효성 임계값 산출 + MATLAB `.mat` export | ⚠️ 경로 수정 필요 |
| `check_sync.py` | 동기화 모드 δ 반응 검증 | ⛔ **오진 — 사용 금지** |
| `_archive/` | `sym.py`(v0) 등 폐기 코드 보관 | — |
| `__pycache__/` | 바이트코드 캐시 | — |

## 실행 순서

```bash
python Simulation/model.py     # 모델 수식 수정 후 구조 자가검사 (양방향 커플링 assert)
python Simulation/runner.py    # 결과 생성 → results/{run}/ + LATEST.json
python Simulation/pf.py        # 참여계수 분석 (runner 이후)
python Simulation/xval.py      # 선형화 유효성 (runner 이후, 경로 수정 후)
python Server/app.py           # 대시보드 (수정 후)
```

`model.py`는 수식을 고쳤을 때만 돌리면 됩니다. `pf.py`·`xval.py`는 `runner.py`가 남긴 파일을 읽으므로 **반드시 그 뒤에** 실행합니다.

### runner.py 주요 옵션

```bash
python Simulation/runner.py                                    # 기본 (SCR 3.0 2.0 1.5 1.0, X/R 1.0)
python Simulation/runner.py --XR 3.0 --SCR 3.0 2.0 1.5 1.0 0.8 --tag xr30
python Simulation/runner.py --J 0.62 --Dp 28                   # 제어 파라미터 변경
python Simulation/runner.py --no-persist                       # 화면 출력만 (디스크 쓰기 없음)
python Simulation/runner.py --no-latest                        # LATEST.json 갱신 생략
```

PSO(Phase 4)에서는 `run(ctrl, SCR_list, persist=False, quiet=True)`로 직접 호출합니다.

## 모델 구조

**상태변수 22 = DC 8 + AC 14**

```
DC: v_pv  i_Lpv  x_vpv  x_ipv  v_dc  i_Less  x_vdc  x_iess
AC: delta  dw  Pf  Qf  phi_d  phi_q  gam_d  gam_q
    i_ld  i_lq  v_od  v_oq  i_od  i_oq
```

**v0(21-state) 대비 핵심 변경**

- `delta`(전력각)를 상태변수로 포함 → 동기화 루프 폐합
- DC↔AC 커플링을 **양방향**으로 유도
  - DC→AC: 인버터 출력전압이 실제 `v_dc`에 비례
  - AC→DC: DC링크가 인버터 소비전류 `i_inv = 1.5(v_od·i_ld + v_oq·i_lq)/v_dc` 만큼 유출
- 동작점을 SCR별로 `fsolve`로 계산 (v0은 `Id0=0.9` 고정)

한 방향만 넣으면 행렬이 블록삼각이 되어 **커플링이 고유값에 전혀 반영되지 않습니다.** v0의 실패 원인이며, `runner.py`가 매 실행마다 `커플링` 열로 감시합니다. 이 값이 0에 가까우면 모델이 퇴화한 것입니다.

## 모드 대역

| 대역 | 주파수 | 물리 모드 |
|---|---|---|
| `sync` | < 5 Hz | 동기화 모드 (δ, Δω) |
| `control` | 5 ~ 100 Hz | 제어루프 · DC-AC 혼합 모드 |
| `lcl` | ≥ 100 Hz | LCL 공진 |

주파수 분류는 **대용 지표**입니다. 논문에는 `pf.py`의 참여계수로 확정한 근거를 씁니다.

기본 파라미터(`Dp/J = 40`)에서 **동기화 모드는 과감쇠되어 실수극으로 분리**됩니다. 진동 모드가 아니므로 `ζ_sync`가 `None`으로 나오는 것이 정상입니다. δ 참여도 0.92~0.98의 실수극이 실제 임계 모드입니다.

## 알려진 문제

### ⛔ `check_sync.py` — 사용 금지

`A[Δω, δ] = 0`을 근거로 "스윙 방정식에 ∂P/∂δ 항이 없다"고 판정하지만, **전차수 모델에서는 0이 정상입니다.**

`K = V·E·cosδ/X`, `ω_n = √(K/J)`는 계통을 대수 방정식으로 취급하는 고전 축소 모델의 공식입니다. 22차 모델에는 계통 동역학(`i_od`, `i_oq`)과 전력 필터(`Pf`)가 상태변수로 있어 δ가 경로를 타고 돌아옵니다.

```
δ → i_od (∂ = +1.18e+04) → Pf (∂ = +3.12e+04) → Δω (∂ = -5.31e-03)
```

이 진단을 따라 스윙 방정식에 ∂P/∂δ 항을 추가하면 **전력 되먹임이 이중 계상되어 모델이 오염됩니다.** 유한차분 검산은 이 오염을 잡지 못합니다(심볼릭과 유한차분이 동일한 f(x)를 미분하므로).

### ⚠️ `xval.py` — 경로 불일치

- 파일명: `x0_SCR{SCR}.npy` → 실제는 `x0_SCR{SCR:.2f}.npy`
- 위치: `results/latest/` → 이제 `LATEST.json` 포인터

### ⚠️ `Server/app.py` — 파일 규칙 불일치

`A_num_SCR{scr}.npy`와 `results/latest/`를 찾습니다. 못 찾으면 **조용히 내장 근사 모델로 폴백**하여 v0 시절 가짜 값을 표시합니다. 수정 전까지 대시보드 결과를 신뢰하지 마세요.

### ⚠️ Phase 4 착수 전 — 안정도 지표 재정의

현재 `ζ_min`은 진동 모드만 봅니다. 임계 모드가 δ 지배 **실수극**이므로 이 상태로 PSO를 돌리면 LCL 공진만 최적화하고 동기화 모드는 건드리지 않습니다. 대역별 ζ 가중합 또는 `max(Re)` 기준으로 바꿔야 합니다.

`runner.py`가 모드 교차(band crossover)를 자동 검출하므로, ζ_min이 SCR에 따라 다른 대역을 가리키는지 먼저 확인하세요.

## 검증 항목

| 항목 | 의미 | 이상 신호 |

| 모드 교차 | ζ_min이 가리키는 대역 변화 | 검출 시 PSO 목적함수 재설계 필요 |
| `loadability_limit` | 정상상태 해 부재 | 소신호 불안정과 **구분** — 2D 경계도에 별도 표기 |
