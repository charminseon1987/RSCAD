# ⚡ 실험 결과 → Obsidian 자동 업데이트 절차

## 실험할 때마다 이 순서로

---

### STEP 1 — 실험 실행 + 결과 저장

```bash
# Flask API 실험
curl -X POST http://localhost:5000/api/jacobian \
  -H "Content-Type: application/json" \
  -d "{\"SCR\":1.5,\"XR\":1.0,\"J\":0.5,\"Dp\":20}" \
  > results/jacobian_SCR1.5_$(date +%Y%m%d).json

# SymPy 실험
python Simulation/sym.py
# → results/ 폴더에 자동 저장
```

---

### STEP 2 — Claude에게 결과 붙여넣기 + 노트 생성 요청

```
[붙여넣을 것]
1. GFM_연구_전체지도.md
2. 해당 버그/실험 노트
3. 실험 결과 JSON

[요청]
"이 결과로 Obsidian 노트를 업데이트해줘.
 - BUG_sym_DC_PI_4차시도.md의 시도 기록 표에 추가
 - 개선된 것 / 남은 문제 분리해서 정리
 - 5차 시도 방향 제안
 - Claude 지식 프롬프트 업데이트"
```

---

### STEP 3 — 노트 업데이트 체크리스트

#### 실험이 성공했을 때 (stable=True)

```
✅ BUG 노트 → status: resolved 변경
✅ GFM_연구_전체지도.md → Phase 상태 업데이트
✅ 새 실험결과 노트 생성 (EXP_날짜_조건.md)
✅ 개념 노트 업데이트 (관련 수치 갱신)
✅ app.py에 SymPy 결과 연동
```

#### 실험이 실패했을 때 (stable=False)

```
✅ BUG 노트 → 시도 기록 표에 추가
✅ 원인 분석 업데이트
✅ 5차 시도 방향 추가
✅ Claude 프롬프트 업데이트
```

---

### STEP 4 — 지식 연결 확인

실험 후 반드시 확인할 연결:

```
이번 결과가 바꾸는 노트:
├── BUG_sym_DC_PI_4차시도.md     ← 시도 기록
├── GFM_연구_전체지도.md          ← 현재 상태
├── 실험_jacobian_SCR1.5_XR1.0.md ← 비교
└── 21차_야코비안_유도가이드.md    ← 수식 근거 확인
```

## 논문 지식화 프롬프트 (결과를 논문으로 연결할 때)

```
[시스템 프롬프트 — 그대로 복사해서 사용]

당신은 GFM 인버터 소신호 분석 결과를 Obsidian 지식으로
변환하는 도구다.

절대 규칙:
▸ = 실험/논문에서 나온 값 (수치, 코드 출력)
※ = 내 해석·판단 (추론, 의미 부여)
반드시 구분할 것. 섞으면 안 됨.

GFM 도메인 검증 기준:
- stable: 모든 Re(λ) < 0
- zeta_min: ≥ 0.64 (UNIFI V3 Category 3)
- A_k(9,6): idc0/(J·ω₀) 이론값과 < 1% 오차
- f_dom: 0.1~10 Hz (VSG 스윙 모드 범위)
- 선형화 유효: Δu_pv < 5%

출력 형식: Obsidian .md (frontmatter 포함)
섹션: 📥입력 / 📤출력 / 📊핵심수치 / 🔍분석 / 🔗연관지식 / 🤖프롬프트
```
