## 내 해석

※ **드룹 규정(3~5 %)과 t_s ≤ 1 s 요구가 현재 플랜트에서 양립하지 않는다고 본다.**
  최적해가 J 하한과 Dp 상한 두 모서리에 동시에 붙었다는 것은, 최적화가 "관성을 더
  줄이고 드룹을 더 뻣뻣하게" 가고 싶은데 요구가 막고 있다는 뜻이다. 모서리에 붙은
  해의 t_s 가 1.31 s 이므로, 상자 안에 1.0 s 를 만족하는 점이 있을 가능성은 낮다 —
  다만 이건 모서리 하나에서 본 추론이고, 상자 안을 조밀하게 쓸어 본 것은 아니다.

※ **PSO 한계가 아니라 상자 한계다.** 이건 추론이 아니라 측정으로 닫혔다 — 드룹
  하한만 3 % → 2 % 로 옮기니 3/3 seed 가 1.11~1.13 으로 넘었다. 탐색 예산을 6배로
  키운 것(5808회)은 못 넘겼고(0.7831), 상자를 조금 넓힌 것은 넘겼다. 묶는 것이
  탐색이 아니라 제약이라는 뜻이다.

※ **묶는 것은 드룹 하한 하나다. 관성 하한은 아니다.** 두 축을 갈라야 한다.
  - 드룹: 3~5 % 에서 Dp 가 5/5 상한에 붙었고, 2~5 % 로 넓히니 **다시** 상한
    (2.000 %)에 붙으면서 score 가 올라갔다. 최적은 계속 상자 밖, 더 뻣뻣한 쪽에
    있다. → 완화가 듣는다.
  - 관성: 3~5 % 에서 J 가 하한에 붙은 것은 **드룹 제약에 눌린 결과**였다고 본다.
    드룹을 2 % 까지 풀어 주니 J 가 H 3.269 s(범위 8 %)로 **안쪽으로 들어왔다.**
    게다가 절단면에서 H 3.0 s 밑은 불안정이다 — J 하한이 안정성 벽과 거의 겹친다.
    → **J 하한을 완화해도 듣지 않는다.**

※ 1차원 절단면으로 완화폭을 정하려 한 것은 틀린 방법이었다. `pso_B14s1` 에서 Dp
  만 움직이면 2.5 % 가 3.0 % 보다 나쁘게 나오는데(0.659 vs 0.8198), 13개를 함께
  풀면 같은 2 % 대가 1.12 다. 나머지 13개가 드룹 3 % 에 맞춰 공적응해 있었기
  때문이다. **이 목적함수에서 한 축만 흔들어 결론을 내면 안 된다.**

⚠ 여전히 **존재하지 않음의 증명은 아니다.** 드룹 3~5 % 안에서 6회(5808회 포함)
  돌려 0.8198 이 최고였다는 관측이고, 상자 내부를 조밀하게 쓸지는 않았다.
  "요구 상자 안에 해가 없다" 를 논문에 쓰려면 격자 쓸기나 다른 탐색기가 더 필요하다.

※ `pso_B35` 의 1.53 은 **규정을 위반해서 산 값**이라고 본다. Dp = 11.9 는 드룹
  0.59 %, 규정보다 5~8배 뻣뻣하다. 어제 시점에는 그 사실을 몰랐다 — Dp 가 감쇠계수
  이면서 동시에 드룹계수라는 것을 환산해 보기 전이었다.

※ Dp 의 이중 역할은 모델 구조에서 온다. `model.py` f[9] 는
  `J·Δω̇ = (Pref−Pf)/w0 − Dp·Δω` 하나뿐이고 별도 감쇠항이 없다. 즉 이 모델에서는
  드룹을 건드리지 않고 감쇠만 조절할 수 없다. 설계 자유도가 하나 줄어든다는 뜻이고,

※ 가상관성이 ESS 에서 전량 나온다는 것은 계산으로 닫혔다. H_equiv 0.0704 s 는 기준
  J 가 주장하는 3.553 s 의 1/50 이다. 커패시터 크기를 키워 메울 수 있는 차이가 아니다.

※ ζ 2차 근사가 1.7 % 로 맞은 것은 뜻밖이다. 스윙 모드가 다른 모드와 거의 섞이지

  다만 모서리 한 점의 일치이고, 범위 전체에서 맞는지는 재지 않았다.

  → **내가 쓰던 3 % 는 임의값이 아니라 Cat I·II 의 법정 하한이었다.** 2 % 는
  규정 위반이 아니라 Cat III 의 하한이다 — 필요한 것: **어느 범주를 주장할지**
  결정 (가정 A7). `--category {I,II,III,2800}` 으로 코드에 넣었고 기본은 `II`

- **나머지 요구값은 여전히 출처가 없다 (가정 A4 의 남은 절반)** — RoCoF
  1.0 Hz/s · ΔP 0.1 pu · 드룹 3~5 % · 전압 드룹 2~5 % 는 통상값으로 넣었다 —
  필요한 것: 적용 계통 규정, 또는 논문이 주장할 값. **지금 수치를 인용 근거로 쓸 수
  없다.** 이 값이 바뀌면 상자가 바뀌고 위 (a)~(c) 판단도 바뀐다

- **ESS 과도출력 여유 0.3 pu 는 연구 가정이다 (가정 A5)** — 원인: 모델에 ESS 정격이
  없다 — 필요한 것: ESS 전력 사양. J 상한이 여기서만 나온다

- `pso_B.json`·`pso_B35.json` 의 `mode` 가 `A-relative` 로 잘못 적혀 있다 — 원인:
  `pso.py` 가 라벨을 하드코딩하고 있었다 (오늘 고쳤다) — 필요한 것: 없음. 두 파일은
  기록이라 덮지 않았고, 올바른 라벨은 `B-mixed (3/14 A안)` 이다. 이 표가 정정이다
