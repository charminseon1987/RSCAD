# 실행 식별자 설계 원칙

> [!abstract] 한 줄
> 식별자는 결과에 영향을 주는 모든 입력을 포함해야 한다.
> 단, **스윕 축은 폴더가 아니라 파일 단위 식별자에 넣는다.**

## 두 단계 판별

새 인수를 추가할 때마다 순서대로 묻는다.

**1단계 — 식별자에 넣는가?**
> "이 값을 바꾸면 저장되는 숫자가 달라지는가?"
> 예 → 넣는다. 아니오 → 안 넣는다. 애매하면 넣는다.

**2단계 — 폴더인가 파일인가?**
> "이 값이 스윕 도중에 변하는가?"
> 변한다 → **파일명** (스윕 축)
> 안 변한다 → **폴더명** (데이터셋 공통 조건)

1단계만 지키면 재현성은 확보되지만 **누적이 불가능해진다.** 2단계가 있어야 스윕을 이어붙일 수 있다.

## 계층 구조

```
results/
└── J0.50_Dp20.0_Kpv0.050_wc62.8_34546d/   ← 폴더: 공통 조건
    │                                          모델 버전, 제어 파라미터 14,
    │                                          물리 상수, 입력 u₀
    ├── A_num_SCR3.0_XR1.0.npy              ← 파일: 점 조건 (스윕 축)
    ├── A_num_SCR1.5_XR2.0.npy
    ├── x0_SCR3.0_XR1.0.npy
    ├── meta.json                            ← points 레지스트리 (누적)
    └── eigenvalue_results.json              ← 점별 결과 (병합)
```

핵심은 `meta.json`이 **선언이 아니라 레지스트리**라는 점이다.

```python
# ❌ 선언형 — 실행할 때마다 덮어씀
{"SCR_list": [1.7, 1.6, 1.5]}

# ✅ 레지스트리형 — 점을 누적
{"points": {"SCR3_XR1": {...}, "SCR1.5_XR2": {...}}, "n_points": 6}
```

## 따라오는 이득 — resume

파일명이 자기 조건을 갖고 있고 메타가 누적되면, **재개가 공짜로 생긴다.**

```python
if not args.force and point_key(SCR, XR) in done:
    continue                      # 이미 계산된 점은 건너뜀
```

88포인트를 돌리다 40번째에서 죽어도 같은 명령을 다시 치면 41번부터 이어간다.
RTDS 장비 시간을 쓰는 실험에서는 이것이 재실행 비용과 예약 재신청을 가른다.

## 실패 사례 두 개

### 1차 사고 — 식별자 불완전 (덮어쓰기)

해시를 제어 파라미터로만 만들고 `--SCR`을 누락했다.

```bash
python runner.py                              # SCR 3.0 2.0 1.5 1.0
python runner.py --SCR 1.7 1.6 1.5 1.4 1.3    # 같은 폴더로 들어감
```

`.npy`는 8개 쌓였는데 `meta.json`의 `SCR_list`는 5개만 기록. 폴더 내용과 메타데이터가 서로 다른 말을 하는 상태.

### 2차 사고 — 과잉수정 (누적 불가)

1차를 고친다고 SCR 목록을 해시에 넣었다. 덮어쓰기는 막혔지만 **스윕 단위가 굳어버렸다.**

- SCR 1.2를 하나 추가하려면 해시가 바뀌어 별도 폴더 생성 → 기존 점과 합칠 수 없음
- 중간 실패 후 이어붙이기 불가 → 매번 처음부터
- X/R도 폴더명에 있어 2D 스윕 하나가 폴더 10개로 쪼개짐

> [!warning] 교훈
> **1차 진단이 틀렸다.** `.npy`는 이미 파일명에 SCR을 갖고 있어 충돌한 적이 없다.
> 충돌한 것은 `meta.json` 하나뿐이었고, 해법은 식별자 강화가 아니라 **메타의 누적화**였다.
> 증상(폴더가 겹침)이 아니라 원인(메타가 선언형)을 고쳤어야 했다.

## 분류표

| 폴더명 (공통 조건) | 파일명 (스윕 축) | 식별자 제외 |
|---|---|---|
| 모델 버전 / 코드 버전 | SCR | 표시 옵션 (`--top`, `--modes`) |
| 제어 파라미터 (PSO 대상 14) | X/R | 출력 경로, 로그 레벨 |
| 물리 상수 (L, C, R) | 일사량·온도 (스윕 시) | 타임스탬프, 실행자 |
| 입력 벡터 u₀ | 부하율 (스윕 시) | 진행 표시, 색상 |
| 수치 설정 (`--tol`, `--T`) | | `--force` |

> 같은 변수라도 **고정하면 폴더, 스윕하면 파일**이다. 일사량을 고정값으로 쓰면 폴더 조건, 스윕 대상으로 삼으면 파일 조건.

## 구현 패턴

```python
def make_run_name(ctrl, tag=''):
    """스윕 축(SCR, XR)은 제외 — 점을 누적할 수 있도록"""
    sig = {'model': MODEL_VERSION, 'ctrl': ctrl,
           'fixed': FIXED, 'inputs': INP}
    h = hashlib.md5(json.dumps(sig, sort_keys=True,
                               default=float).encode()).hexdigest()[:6]
    return f"J{ctrl['J']:.2f}_Dp{ctrl['Dp']:.1f}_{h}" + (f"_{tag}" if tag else '')


def point_key(SCR, XR):
    return f"SCR{SCR:g}_XR{XR:g}"          # :g → 3.0과 3이 같은 키
```

- `sort_keys=True` — dict 순서로 해시가 흔들리지 않게
- `default=float` — numpy 스칼라 직렬화
- `:g` 포맷 — `3.0`과 `3`이 다른 점으로 갈라지지 않게
- 앞부분은 사람용(주요 파라미터), 해시는 기계용(완전성)
- **재실행 시 잔여 파일을 지우지 않는다** — 누적이 목적이므로

## 확장 — CHIL 단계

RTDS로 넘어가면 폴더 조건에 추가될 것들.

- RSCAD 케이스 파일 해시 (회로가 바뀌면 결과가 바뀐다)
- DSP 펌웨어 빌드 ID
- GTIO 스케일링 상수
- 타임스텝 / substep 설정

pre-processor 재컴파일이 필요한 SCR·X/R은 여전히 **스윕 축**이므로 파일 조건이다.
소프트웨어 단계에서 이 구분을 습관화하지 않으면 하드웨어 단계에서 사고가 난다.
