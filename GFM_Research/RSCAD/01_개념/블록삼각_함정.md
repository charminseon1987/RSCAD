# 블록삼각 함정

> [!abstract] 한 줄
> 두 서브시스템의 커플링을 **한 방향만** 넣으면 시스템 행렬이 블록삼각이 되고,
> 그 커플링 항은 **고유값에 아무 영향을 주지 못한다.**

## 수학

블록 형태의 시스템 행렬을 생각한다.

$$
A = \begin{bmatrix} A_{11} & A_{12} \\ A_{21} & A_{22} \end{bmatrix}
$$

$A_{12} = 0$ 또는 $A_{21} = 0$ 이면 $A$는 **블록삼각**이고,

$$
\det(A - \lambda I) = \det(A_{11} - \lambda I)\cdot\det(A_{22} - \lambda I)
$$

$$
\therefore\ \mathrm{eig}(A) = \mathrm{eig}(A_{11}) \cup \mathrm{eig}(A_{22})
$$

**비어 있지 않은 쪽 블록에 무엇을 넣든 고유값은 변하지 않는다.**
행렬을 아무리 크게 만들어도 안정도 해석 결과는 두 서브시스템을 따로 푼 것과 동일하다.

> 커플링은 여전히 **응답 형상**에는 영향을 준다(고유벡터·잔여값이 바뀜).
> 그러나 **고유값·감쇠비·안정도**에는 영향이 없다.
> 소신호 안정도 연구에서는 사실상 커플링이 없는 것과 같다.

## 실제 사례 — 21차 GFM 모델 v0

DC 8차와 AC 13차를 결합한 21차 모델을 만들고, DC→AC 커플링 항 하나를 좌하단에 넣었다.

```python
A_num = np.block([[A_DC,              np.zeros((8,13))],   # ← 우상단 0
                  [np.zeros((13,8)),  A_AC            ]])
A_num[8, 5] = idc0 / (J * w0)        # 좌하단 한 칸만
```

수치 확인 결과:

```
커플링 유무 고유값 최대차이     = 0.000e+00
21차 고유값 vs (DC ∪ AC) 차이  = 1.179e-12
```

즉 **21차를 돌린 결과가 13차 AC 모델만 돌린 결과와 완전히 동일**했다.
DC측 8개 상태는 계산에는 참여했지만 결과에는 기여하지 않았다.

### 왜 놓쳤는가

- 검증 코드가 `idc0/(J·w0)`로 대입한 값을 `idc0/(J·w0)`와 비교하는 **항등식**이었다 → 항상 통과
- DC 8×8이 대각행렬이라 항상 안정 → 전체 결과가 그럴듯해 보였다
- "커플링 항을 넣었다"는 사실만 확인하고 "효과가 있는가"는 확인하지 않았다

### 물리적으로도 틀렸다

인버터는 DC 버스에서 전력을 끌어간다. AC측 전력 변동은 반드시 DC 버스 전압에 되먹임된다.
그 경로($A_{12}$)를 0으로 둔 것은 수학적 실수 이전에 **물리를 빠뜨린 것**이다.

$$
i_{inv} = \frac{1.5(v_{od}i_{ld} + v_{oq}i_{lq})}{v_{dc}}
$$

이 항이 $\dot{v}_{dc}$ 에 들어가야 $\partial \dot v_{dc}/\partial i_{ld} \neq 0$ 이 되고 우상단 블록이 채워진다.

## 일반화 — 언제 의심하는가

두 서브시스템을 결합할 때 **양방향 물리 경로가 있는지** 먼저 묻는다.

| 결합 | 정방향 | 역방향 (놓치기 쉬움) |
|---|---|---|
| DC ↔ AC (인버터) | 변조: 출력전압 ∝ v_dc | 전력 보존: DC 전류 = P_ac/v_dc |
| 기계 ↔ 전기 (발전기) | 토크 → 회전 | 전기 부하 → 반작용 토크 |
| 열 ↔ 전기 | 온도 → 파라미터 | 손실 → 발열 |
| 제어기 ↔ 플랜트 | 지령 → 동작 | 측정 → 피드백 |
| 인버터 ↔ 계통 | 출력 → 계통 전압 | 계통 임피던스 → 단자 전압 |

에너지가 오가면 반드시 양방향이다. **한 방향만 나왔다면 물리를 빠뜨린 것이다.**

## 상시 감시 방법

행렬을 만들 때마다 커플링 블록을 인위로 0으로 만들고 고유값 변화를 잰다.

```python
def coupling_effect(A, n1):
    A_cut = A.copy()
    A_cut[n1:, :n1] = 0          # 정방향 블록
    A_cut[:n1, n1:] = 0          # 역방향 블록
    e1 = np.sort_complex(linalg.eigvals(A))
    e2 = np.sort_complex(linalg.eigvals(A_cut))
    return np.max(np.abs(e1 - e2))
```

- **0에 가까우면 블록삼각으로 퇴화** → 즉시 중단
- 이 값 자체가 "결합 모델이 필요한 이유"의 정량 근거가 된다

심볼 수준에서도 확인 가능하다.

```python
ac2dc = [(i,j) for i in range(n1) for j in range(n1, N) if A_sym[i,j] != 0]
assert ac2dc, "역방향 커플링 없음 → 블록삼각"
```

현재 `runner.py`는 매 실행마다 `커플링 효과` 열을 출력하고,
`model.py`는 import 시 양방향 비영 원소를 assert로 검사한다.

## 파급 — 결론이 뒤집힌다

블록삼각인 채로 다음 단계에 진입하면 **참여인자 분석에서 DC 상태의 AC 모드 기여도가 0으로 나온다.**
그러면 "DC측은 무의미하므로 축소 모델" 판정이 내려지는데,
이는 물리 때문이 아니라 **코드 구조 때문**이다.

수정 후 실제 결과: 모든 SCR에서 DC·AC 혼합 모드가 2~4개 존재.
→ 22차 유지 판정. [[Phase03_참여인자]]
